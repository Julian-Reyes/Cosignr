# Cosignr: notes for Claude

Cosignr is a music discovery site built around **cosigns**: one artist publicly vouching for another (a feature, a remix, a tour support slot, a label signing, a shout-out). The pitch is "discover new music through the artists you already trust." It started as an unfinished portfolio mockup and may become a real product, so build it as one.

Read `PROGRESS.md` for where things stand and `WALKTHROUGH.md` for the human-facing explanation. Update both whenever you finish a task (see "Keeping the docs current").

## Running it

```
npm install          (once; Node 22.12+)
npm run dev          http://localhost:4321/Cosignr/   live reload while editing
npm run build        static site in dist/ (what GitHub Pages serves)
npm run preview      serve dist/ at http://localhost:4321/Cosignr/
# add ?dev for the dev panel, ?src=wikimedia to force an image source, ?q=chicago to pre-fill search
```

Pages read `data/*.json` at build time, so after refreshing data, rebuild (or restart `npm run dev`).

Refresh generated data, in this order: `node scripts/fetch-cosigns.mjs`, `node scripts/fetch-tours.mjs`, `node scripts/fetch-extended.mjs`, `node scripts/fetch-sources.mjs`, `node scripts/fetch-upcoming.mjs`, `node scripts/fetch-profiles.mjs`, `node scripts/fetch-stats.mjs` (extended ranks by yesterday's fame from stats.json; stats reads cosigns, tours and upcoming) (the scripts need no npm packages; Last.fm needs `LASTFM_API_KEY`, Ticketmaster `TICKETMASTER_API_KEY` in `.env`).

## Rules

- **Never invent real-world facts presented as real.** Anything placeholder lives under an artist's `demo` key in artists.json and should be labelled as demo in the UI once real data exists. Unknown facts are `null`, not guesses.
- **Artist page order (Julian, 2026-10-16):** Cosigns first, then Cosigned by; side by side on desktop, stacked below 900px.
- **Artist page lists show 10 rows, then "Show more" adds 10** (Julian, 2026-10-15); the rest comes from the per-artist JSON. Both lists have sort tabs Strongest / Recent / Famous (Julian, 2026-10-16); Cosigns opens on Strongest, Cosigned by on Famous. Islands with buttons use `client:load`: `client:visible` lost the first click.
- **Who gets an artist page (Julian, 2026-10-15):** the 12 roster artists plus the top 5 cosigners of each (`data/extended.json`, ~49). Extended artists are **light pages**: photo, stats, hometown, genre, upcoming shows, and only the cosigns we already have with the roster. Their own catalogs are not crawled. Hundreds or thousands of pages come later (see the scaling plan in PROGRESS.md).
- **Genre:** hand-written in artists.json wins; otherwise the most-voted MusicBrainz genre (`profiles.json`), title-cased; null if none.
- **Hometown = where the artist was born (person) or formed (group)** (Julian, 2026-10-15). Hand-written `hometown` in artists.json wins; otherwise MusicBrainz begin-area, then area. Never blank if MusicBrainz has anything; country-only ("United Kingdom") is fine. Generated hometowns look the same as hand-written ones on the page.
- **Image licensing is non-negotiable.** Only use images from: Wikimedia Commons (show author + license, linked), Spotify (link back to the artist on Spotify, per Spotify's developer terms), or press kits the artist/label has given permission for. Never scrape Google Images, Instagram, etc. Every rendered photo must have its credit reachable (hover caption + footer "Photo credits").
- **No secrets in the repo or the browser.** This is a static GitHub Pages site. API keys go in GitHub Actions secrets and are used at build time only (see Milestone 1).
- **Be polite to free APIs.** Send a descriptive User-Agent. MusicBrainz is max 1 request/second. Cache results in `data/` instead of calling APIs from the browser.
- **Wikimedia thumbnails** only exist at standard widths (330, 500, 960, 1280...). Other widths, like 400, return an error.
- **Spotify popularity/followers are gone for new apps** (Feb 2026). Don't plan features around them; the Cosignr score uses Deezer + Last.fm.
- **Check Deezer IDs by their albums.** fetch-extended.mjs does this automatically: it tries every Deezer ID from MusicBrainz and Wikidata (P2722) and keeps the first page with albums (Daft Punk, Kygo, FERG had empty duplicates linked on MusicBrainz). MusicBrainz sometimes links to an empty duplicate Deezer page, and common names (Jackal) can share one page between several artists. Put known-bad metrics under the artist's `caveats` (key = source) so they're excluded instead of shown.
- **Deezer is not an approved image source.** Use it for numbers only, not `picture_xl`, unless licensing is checked first.
- **MusicBrainz credits are messy.** DJ-mix segments, mashups, fan mashup tapes and bootleg edits credit big names who never vouched, and early mixtapes overcount duo partners. Fame ranking pushes one-offs to the top, so check every roster artist's top 4 cosigners after any rule change.
- **Last.fm needs "+" encoded twice** in artist names (`%252B`), or it reads it as a space and returns a broken duplicate page ("Florence   The Machine", 20k listeners instead of 4M). Its MusicBrainz ID lookup can also land on such a duplicate, so check the returned name.
- **MusicBrainz `release?track_artist=X` excludes releases credited to X.** Use both `artist=X` and `track_artist=X` to get everything X appears on.
- **Never look up an extended artist on Last.fm by plain name.** "Ye" is a different, smaller artist; Kanye West's page is the real one. fetch-stats.mjs verifies extended artists like cosigner fame and caches the page name (`lastfmVerified`). **Spotify also has empty duplicate artist pages** (Beyoncé): keep the ID whose oEmbed has a photo, Wikidata's first.
- **Last.fm merges same-name artists into one page** and tags it with one of their MusicBrainz IDs ("JENNIE" carries a Finnish Jennie's ID). Never trust a name match whose Last.fm ID differs from ours; unknown fame is safer than wrong fame.
- **Default image source is Spotify** (`DEFAULT_SOURCE` in src/lib/shared.js). Pages are built with it; the dev panel swaps images in the browser (elements marked `data-img` / `data-credit`). The dev panel can switch to the others for comparison.
- **Spotify oEmbed** (`open.spotify.com/oembed`) needs no key but returns a 320px image. Swapping the size code in the URL to `ab6761610000e5eb` gives 640px.
- Keep the established look: plain "Cosignr" wordmark in Nunito 800 (no checkmark box, Julian 2026-10-16; Roboto was tried and dropped), dark grey (`--nav`) text on Login/Sign up, blue top bar, dark sticky nav, white main, light-blue Top Artists band, peach/blue chips, Nunito. **Astro with React islands** (moved 2026-10-15, plan in ASTRO.md). Still static, still GitHub Pages.
- **Astro rules:** `base` is `/Cosignr`, so every internal link and local file URL starts with `import.meta.env.BASE_URL` (`BASE` in data.js). Only Astro pages may import `src/lib/data.js`; islands get small props, so raw data files never reach the browser. Islands talk through window events (`cosignr:search`, `cosignr:view`, `cosignr:set-view`). Pin exact package versions that are at least two weeks old.
- **Git: no AI attribution.** Never add `Co-Authored-By: Claude` (or any Claude/AI attribution) to commit messages or PR descriptions. Commits are authored by Julian only.
- **Wikipedia tour infoboxes** have a `support_acts` field; trust only linked names, resolved to MusicBrainz via Wikidata P434. A redirect into a section (`tofragment`, "LA Priest" → "Late of the Pier#…") is a different act: skip it. Wikidata can hold two MusicBrainz IDs for one artist (Drake): prefer the roster one. Tour items often lack a performer on Wikidata, so also read the "<Artist> concert tours" category.
- **MusicBrainz events:** festivals label the whole line-up "support act"; read only Concert (or untyped) events with ≤3 main performers. A solo project's touring band shows up as "instrumental/vocal supporting musician" (Tame Impala ↔ Nick Allbrook), not "member of band". Those still count as cosigns (Julian, 2026-10-15: Tame Impala is one person, so a touring musician was chosen by him); only "member of band" and "is person" are excluded.
- **Ticketmaster:** never match by name ("Saba" → Sabaton, "Drake" → Drake White). Match roster artists by MusicBrainz or Spotify ID from `externalLinks`; its MusicBrainz IDs can be stale (Rezz, Saba) and some pages have no links at all (The xx). It also tags tribute/DJ nights with the real artist ("Drake vs Bad Bunny Dance Night").
- Escape all data before putting it in HTML. Astro `{}` and React escape automatically; `esc()` in src/lib/shared.js for HTML built as strings (`set:html`, `dangerouslySetInnerHTML`). Data will eventually come from users.

## Data model (data/artists.json)

```jsonc
{
  "id": "saba",                          // slug, also the press image filename
  "name": "Saba", "genre": "Hip-Hop", "hometown": "Chicago, IL" | null,
  "ids": { "wikidata", "spotify", "musicbrainz", "lastfm", "deezer" },  // join keys for every source
  "original": "saba.png",                // legacy mockup image
  "focus": { "wikimedia": "center 85%" },// optional object-position per source
  "caveats": { "deezer": "why" },        // optional: source whose numbers are unreliable for this artist
  "demo": { ... }                        // optional: any placeholder values, labelled as demo in the UI
}
```
Top-level `featured`, `trending`, `top` are ordered lists of artist IDs.

## Cosigns (data/cosigns.json)

A cosign is one artist vouching for another, grouped per (from, to) pair with up to 3 evidence songs:
`{ from, to (MusicBrainz IDs), types: [feature|collab|remix], songs, vouches, first, last, evidence: [{title, recording, date, type, url}] }`.
`artists` maps MusicBrainz ID → `{ name, id? }` (`id` = our roster ID).

Rules: "A feat. B" → A cosigns B. "A & B" → both ways. B remixed A → A cosigns B. Only songs on an Official release count (no bootlegs, fan mashup tapes, DJ edits). Songs released after the cosigner died or split up don't count (Julian, 2026-10-15). Skipped: DJ-mix segments, mashups/medleys, band ↔ own member, pairs with no roster artist.

Ranking of "Cosigned by" chips (Julian, 2026-10-15: fame counts most): cosigner's Last.fm listeners (`stats.json` → `cosigners`), then `vouches` (feature + remix songs), then `songs`, then `last`. Unknown fame ranks last.

**Tours (data/tours.json)**, same shape with `types: [tour|band]`, `tours` (count) and evidence `{type, title|null, date, source: Wikipedia|MusicBrainz, url, shows?}`. Headliner cosigns the opener; one tour counts once. `band`: hiring someone for your touring band is a cosign (Julian, 2026-10-15). **Upcoming (data/upcoming.json)** from Ticketmaster: `{from, to, types: ["upcoming"], shows, first, last, next: {tour, date, city, url}}`. The page merges songs, tours, band and upcoming for a pair into one chip; each tour, a band spot and an upcoming run count as vouches. Ticketmaster is live data: rebuilt nightly, hidden once past, no revenue from it. Setlist.fm's terms forbid storing its data.

Wikidata is the hub for finding IDs: P1902 Spotify, P434 MusicBrainz, P3192 Last.fm, P18 Commons image. Small artists often aren't on Wikidata; MusicBrainz URL relations usually have their Spotify link.

## Roadmap (details and status in PROGRESS.md)

- **Milestone 0: data-driven page + image sources.** One JSON drives every section, text is rendered over photos instead of baked in, and there are three image sources plus a developer toggle.
- **Milestone 1: real data + infrastructure**
  - Stats: Spotify popularity (0–100) and followers, Last.fm listeners/playcount. Retire the fake "streams" numbers.
  - Other free sources: MusicBrainz (relationships, area, dates), Wikidata (hometown, genres, socials), Wikipedia (bio), Deezer (fan count, 1000px images, 30s previews, no key), ListenBrainz, TheAudioDB.
  - Real cosigns: each cosign is an evidence record (from, to, type, date, source URL). Seed it from MusicBrainz collaborations/remixes, Setlist.fm tour support and labels, then curation, then user submissions.
  - Nightly GitHub Action runs the fetch scripts with secrets and commits `data/*.json`.
  - Accounts and user cosigns (Supabase or Firebase), artist detail pages, a "who cosigned who" graph view.
  - Check Spotify Web API access when registering the app: endpoints were restricted for new apps in Nov 2024 (related artists, recommendations, audio features).
