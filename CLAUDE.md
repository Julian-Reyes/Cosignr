# Cosignr: notes for Claude

Cosignr is a music discovery site built around **cosigns**: one artist publicly vouching for another (a feature, a remix, a tour support slot, a label signing, a shout-out). The pitch is "discover new music through the artists you already trust." It started as an unfinished portfolio mockup and may become a real product, so build it as one.

Read `PROGRESS.md` for where things stand and `WALKTHROUGH.md` for the human-facing explanation. Update both whenever you finish a task (see "Keeping the docs current").

## Layout

```
cosignr/
  index.html              Page shell. Sections are empty containers filled by js/app.js
  home.css                All styles. Color tokens on :root (blue #4BD6FF, peach #FEC39B, nav #333)
  js/app.js               Rendering, interactions, dev panel. No build step, no framework
  data/artists.json       HAND-CURATED source of truth (names, IDs, featured/trending/top lists)
  data/sources.json       GENERATED by scripts/fetch-sources.mjs. Never edit by hand
  data/stats.json         GENERATED by scripts/fetch-stats.mjs (Deezer fans, Last.fm, Cosignr score)
  data/snapshots/         GENERATED daily copies of the numbers, for trending/rank changes later
  scripts/fetch-sources.mjs  Pulls image URLs + credits from free sources
  scripts/fetch-stats.mjs    Pulls stats; Last.fm only if LASTFM_API_KEY is in .env or the env
  .github/workflows/refresh-data.yml  Nightly run of both scripts, commits data/
  images/press/           Press-kit photos, named <artist-id>.jpg. Only with permission
  *.png (root)            Original 2019 mockup images ("Original" source). Some have text baked in
  indexOld.html           Untouched copy of the original page. Don't edit
  images/favicon.png      Placeholder favicon copied from the portfolio site
```

## Running it

`fetch()` needs a server (opening index.html as a file won't load the JSON):

```
python3 -m http.server 8000   (from the project root)
# http://localhost:8000/?dev        dev panel on
# http://localhost:8000/?src=spotify   force an image source
```

Refresh generated data: `node scripts/fetch-sources.mjs` and `node scripts/fetch-stats.mjs` (Node 18+, no dependencies; Last.fm needs `LASTFM_API_KEY` in `.env`).

## Rules

- **Never invent real-world facts presented as real.** Anything placeholder lives under an artist's `demo` key in artists.json and should be labelled as demo in the UI once real data exists. Unknown facts are `null` (e.g. hometowns for G Jones, Jackal), not guesses.
- **Image licensing is non-negotiable.** Only use images from: Wikimedia Commons (show author + license, linked), Spotify (link back to the artist on Spotify, per Spotify's developer terms), or press kits the artist/label has given permission for. Never scrape Google Images, Instagram, etc. Every rendered photo must have its credit reachable (hover caption + footer "Photo credits").
- **No secrets in the repo or the browser.** This is a static GitHub Pages site. API keys go in GitHub Actions secrets and are used at build time only (see Milestone 1).
- **Be polite to free APIs.** Send a descriptive User-Agent. MusicBrainz is max 1 request/second. Cache results in `data/` instead of calling APIs from the browser.
- **Wikimedia thumbnails** only exist at standard widths (330, 500, 960, 1280...). Other widths, like 400, return an error.
- **Spotify popularity/followers are gone for new apps** (Feb 2026). Don't plan features around them; the Cosignr score uses Deezer + Last.fm.
- **Check Deezer IDs by their albums.** MusicBrainz sometimes links to an empty duplicate Deezer page, and common names (Jackal) can share one page between several artists. Put known-bad metrics under the artist's `caveats` (key = source) so they're excluded instead of shown.
- **Deezer is not an approved image source.** Use it for numbers only, not `picture_xl`, unless licensing is checked first.
- **Default image source is Spotify** (`DEFAULT_SOURCE` in app.js). The dev panel can switch to the others for comparison.
- **Spotify oEmbed** (`open.spotify.com/oembed`) needs no key but returns a 320px image. Swapping the size code in the URL to `ab6761610000e5eb` gives 640px.
- Keep the established look: blue top bar, dark sticky nav, white main, light-blue Top Artists band, peach/blue chips, Nunito. Plain HTML/CSS/JS until there's a real reason for a framework.
- **Git: no AI attribution.** Never add `Co-Authored-By: Claude` (or any Claude/AI attribution) to commit messages or PR descriptions. Commits are authored by Julian only.
- Escape all data before putting it in HTML (`esc()` in app.js). Data will eventually come from users.

## Data model (data/artists.json)

```jsonc
{
  "id": "saba",                          // slug, also the press image filename
  "name": "Saba", "genre": "Hip-Hop", "hometown": "Chicago, IL" | null,
  "ids": { "wikidata", "spotify", "musicbrainz", "lastfm", "deezer" },  // join keys for every source
  "original": "saba.png",                // legacy mockup image
  "focus": { "wikimedia": "center 85%" },// optional object-position per source
  "caveats": { "deezer": "why" },        // optional: source whose numbers are unreliable for this artist
  "demo": { "cosignedBy": [...] }        // placeholder cosigns until the evidence model exists
}
```
Top-level `featured`, `trending`, `top` are ordered lists of artist IDs.

Wikidata is the hub for finding IDs: P1902 Spotify, P434 MusicBrainz, P3192 Last.fm, P18 Commons image. Small artists often aren't on Wikidata; MusicBrainz URL relations usually have their Spotify link.

## Roadmap (details and status in PROGRESS.md)

- **Milestone 0: data-driven page + image sources.** One JSON drives every section, text is rendered over photos instead of baked in, and there are three image sources plus a developer toggle.
- **Milestone 1: real data + infrastructure**
  - Stats: Spotify popularity (0–100) and followers, Last.fm listeners/playcount. Retire the fake "streams" numbers.
  - Other free sources: MusicBrainz (relationships, area, dates), Wikidata (hometown, genres, socials), Wikipedia (bio), Deezer (fan count, 1000px images, 30s previews, no key), ListenBrainz, TheAudioDB.
  - Real cosigns: each cosign is an evidence record (from, to, type, date, source URL). Seed it from MusicBrainz collaborations/remixes, Setlist.fm tour support and labels, then curation, then user submissions.
  - Nightly GitHub Action runs the fetch scripts with secrets and commits `data/*.json`.
  - Accounts and user cosigns (Supabase or Firebase), artist detail pages, a "who cosigned who" graph view.
  - Check Spotify Web API access when registering the app: endpoints were restricted for new apps in Nov 2024 (related artists, recommendations, audio features).
